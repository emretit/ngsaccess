## Ortak bileşen önerisi

**En az değişiklik:** yeni `src/components/shared/TableStateRow.tsx`; temel `ui/table.tsx` bileşenini veri durumuyla ilişkilendirmeyin. TableStateRow yalnız **TableBody içinde** bir TableRow + TableCell üretir; Table veya TableHeader oluşturmaz ve parent'ın erken dönüşünü tek başına çözmez.

Taslak API (yalnız öneri; kod yazılmadı):

```ts
type TableStateRowProps = {
  colSpan: number;
  className?: string;
} & (
  | { state: "loading"; label?: string }
  | {
      state: "empty";
      title: string;
      description?: string;
      icon?: LucideIcon;
      action?: { label: string; onClick: () => void };
    }
  | {
      state: "error";
      title?: string;
      description?: string;
      onRetry?: () => void;
    }
);
```

- Empty dalı mevcut `EmptyState compact`, error dalı `ErrorState compact`, loading dalı erişilebilir metinli spinner üretir. `role=status`/`aria-busy` yalnız uygun içerikte kullanılır; spinner dekoratif olabilir. Hücre tam genişlik ve hizalama/padding'i merkezileştirir. “Bu sayfada eşleşme yok, tarama sürüyor” mesajı empty title/description ile ifade edilebilir; pagination dışarıda kalır.
- İlk kullanıcılar: `AdminDevicesPanel.tsx` (**6**), `admin/components/UserTable.tsx` (**4**) + `AdminUsersPanel.tsx` parent durumu, `admin/projects/ProjectsTable.tsx` (**5**) + `AdminProjectsContent.tsx` parent durumu, `HolidayCalendarManager.tsx` (**3**), `RolesSettings.tsx` (**6**). Sayfa/page-size değişimi ve filtreler TableStateRow API'sine taşınmamalı.
- UserTable/ProjectsTable mevcut data-only props'a durum bilgisi eklenerek kullanılabilir; parent yükleme/boş koşulu masaüstü tablonun çağrısını engellememeli. ResponsiveResults desktop tabloyu sürekli almalı; mobile kendi kutu/kart durumunu koruyabilir.
- QuerySectionBoundary değişikliği ayrı iştir: mevcut sabit `<section>` başarılı dalı ve `<div>` hata dalı nedeniyle tbody içine doğrudan kullanılamaz. Gerektiğinde `TableBodyQueryBoundary` gibi yalnız `children` ve `(error, retry) => ReactNode` fallback alan, başarılı dalı fragment olan tabloya özel bir error boundary önerilir. Sorguyu çağıran alt bileşen onun içinde, TableHeader dışında olmalıdır. TableStateRow error prop'u tek başına useQuery'nin fırlattığı hatayı yakalamaz.
- Genel boundary'ye opsiyonel fallback eklemek tüm bölümü yeniden çizerek header'ı koruyabilir; ancak küçük ilk adım olarak satır yardımcısı + tablo kabuğunu dışarı alma daha sınırlı etki alanına sahiptir. MasterDetailListLayout, TreePanel, PaginationBar ve LoadMoreFooter için değişiklik gerekmiyor.
