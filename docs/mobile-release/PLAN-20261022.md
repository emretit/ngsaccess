### Faz 1 — MOB-N05 OS-kill ziyaretçi kabulü
Kabul: (a) yanıt kaybı + yeniden başlatma sonrası tek ziyaretçi, (b) bilinmeyen sonuçta sessizce yeni requestId yok, (c) başka hesap/proje niyeti göremez; logout/expiry temizliği doğru.

Ortam: Android emülatör (`ngs_release_16k_20261022` AVD veya API 36) + test APK `15a91f31…b377`. Ağ ve süreç kontrolü burada tam: `adb shell cmd connectivity airplane-mode enable`, `adb shell am kill` / `kill -9 <pid>`. iOS sim'de ağ kesmek güvenilir değil, o yüzden iOS'ta yalnız Senaryo A (`xcrun simctl terminate` ile kill) çalıştırılır.

- **1.1** Emre test çalışanını seçer. Çalışan izole bir test projesinde olmalı; gerçek personel olmamalı. Ziyaretçiler sahte isimle girilir (`Test Ziyaretçi N05-A`).
- **1.2 Senaryo A**: Ziyaretçi formunu doldur → Oluştur → istek gider gitmez uçak modu → `kill -9` → uçak modu kapat → uygulamayı aç. Beklenen: receipt sorgusu kaydı bulur, liste tek kayıt gösterir, ikinci create yok. Backend sayımı web ziyaretçi listesinden yapılır (Orca tarayıcı, salt okuma).
- **1.3 Senaryo B**: Önce uçak modu → Oluştur → kill → ağ aç → aç. Beklenen: receipt null → niyet silinmez, kullanıcıya "tekrar dene" gösterilir → açık retry aynı requestId ile gider → tek kayıt.
- **1.4 Senaryo C**: Bekleyen niyet varken logout → başka test hesabıyla giriş (varsa) → niyet görünmez. Aynı hesaba dönünce kurtarılabilir.
- **1.5 Web akışı**: Ziyaretçiyi web'den aktive et → mobil detay yenilenir → mobilde düzenle → web'de iptal → kısa süreli ikinci ziyaretçide süre dolumu. Bu adım canlı DB'ye yazar; Emre onayı şart.
- **1.6** Kanıt dosyası: senaryo, zaman (TR), build/hash, beklenen/gerçek, sayım. Ekran görüntüleri `/tmp`'de kalır, repoya girmez.
