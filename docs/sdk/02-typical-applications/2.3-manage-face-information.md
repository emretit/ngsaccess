# Yüz Bilgisi Yönetimi (Manage Face Information)

> **Kaynak:** Device Network SDK (Card-Based Access Control) Developer Guide V6.1.5.X — Bölüm 2.3, s.25–27

## Özet

Yüz tanıma terminalleri (DS-K1T671M, DS-K1T672 vb.) için **çalışanın yüz fotoğrafını** cihaza işlemek + sorgulamak. Yüz **karta bağlı** çalışır — önce kart eklenmiş olmalı ([2.2 Manage Card Information](./2.2-manage-card-information.md)).

## Önkoşullar
1. `NET_DVR_Init()` çağrılmış
2. `NET_DVR_Login_V40()` ile cihaza bağlanılmış
3. **İlgili kart cihaza işlenmiş** (yüz bağımsız kayıt değil)

## İş Akışı (PDF Figure 2-4)

```
NET_DVR_Init → NET_DVR_Login_V40
  → NET_DVR_GetDeviceAbility (ACS_ABILITY, Node: <FaceParam>)
  → NET_DVR_StartRemoteConfig:
        Get:   CMD = NET_DVR_GET_FACE_PARAM_CFG (2507)
        Apply: CMD = NET_DVR_SET_FACE_PARAM_CFG (2508)
  → NET_DVR_SendRemoteConfig (dwDataType: ENUM_ACS_INTELLIGENT_IDENTITY_DATA)
  → NET_DVR_StopRemoteConfig
  → NET_DVR_Logout / NET_DVR_Cleanup
```

## Kullanılan API'ler
- `NET_DVR_GetDeviceAbility` — `<FaceParam>` node desteği
- `NET_DVR_StartRemoteConfig` — `NET_DVR_GET_FACE_PARAM_CFG` (2507) / `NET_DVR_SET_FACE_PARAM_CFG` (2508)
- `NET_DVR_SendRemoteConfig` — `ENUM_ACS_INTELLIGENT_IDENTITY_DATA`

## İlgili Yapılar
- **`NET_DVR_FACE_PARAM_CFG`** (s.179) — yüz parametreleri
  - `byCardNo[]` — kart numarası (yüz hangi karta bağlı)
  - `dwFaceID` — yüz ID (1+)
  - `byFaceType` — yüz tipi
  - `dwFaceLen` — fotoğraf data uzunluğu
  - `pFaceBuffer` — JPEG buffer pointer
- **`NET_DVR_FACE_PARAM_COND`** (s.180) — sorgulama koşulu

## ISAPI Karşılığı

ngsaccess'in tercih ettiği yol — Convex'ten HTTP fetch ile:
```http
POST /ISAPI/Intelligent/FDLib/FaceDataRecord?format=json HTTP/1.1
Content-Type: multipart/form-data; boundary=...

--boundary
Content-Disposition: form-data; name="FaceDataRecord"; filename="record.json"
Content-Type: application/json

{
  "faceLibType": "blackFD",
  "FDID": "1",
  "FPID": "1001",
  "name": "Ahmet"
}

--boundary
Content-Disposition: form-data; name="img"; filename="face.jpg"
Content-Type: image/jpeg

<binary jpeg data>

--boundary--
```

> **Önemli:** Fotoğraf formatı **JPEG**, çözünürlük genelde 480x640 - 1080x1920 arası, file size < 200KB.

## Sample Code (HCNetSDK)
PDF s.27 başlangıcında basit örnek. Detay için PDF s.179 (struct) ile birlikte:
```c
NET_DVR_FACE_PARAM_CFG struFaceCfg = {0};
struFaceCfg.dwSize = sizeof(struFaceCfg);
strncpy((char*)struFaceCfg.byCardNo, "12", ACS_CARD_NO_LEN);
struFaceCfg.dwFaceID = 1;
struFaceCfg.byFaceType = 1;

// Yüz fotoğrafını dosyadan oku
FILE *fp = fopen("face.jpg", "rb");
fseek(fp, 0, SEEK_END);
DWORD len = ftell(fp);
fseek(fp, 0, SEEK_SET);
struFaceCfg.dwFaceLen = len;
struFaceCfg.pFaceBuffer = (char*)malloc(len);
fread(struFaceCfg.pFaceBuffer, 1, len, fp);
fclose(fp);

NET_DVR_SendRemoteConfig(lHandle, ENUM_ACS_INTELLIGENT_IDENTITY_DATA,
    (char*)&struFaceCfg, sizeof(struFaceCfg));
```

## ngsaccess Tarafında Notlar

### Mevcut Yaklaşım
`docs/HIKVISION_ISAPI_FACE_RECOGNITION_VALUE_SERIES.md`'de Value Series cihazlar için ISAPI yüz tanıma akışı detaylıdır. Önce orayı kontrol et.

### Önerilen Flow (Convex)
```typescript
// convex/actions/hikvision/uploadFace.ts (önerilen)
export const uploadFace = action({
  args: { deviceId: v.id("devices"), employeeId: v.id("employees"), photo: v.bytes() },
  handler: async (ctx, { deviceId, employeeId, photo }) => {
    const device = await ctx.runQuery(...);
    const employee = await ctx.runQuery(...);

    // multipart/form-data oluştur
    const form = new FormData();
    form.append("FaceDataRecord", JSON.stringify({
      faceLibType: "blackFD",
      FDID: "1",
      FPID: employee.cardNumber,
      name: employee.name,
    }));
    form.append("img", new Blob([photo], { type: "image/jpeg" }));

    const res = await fetch(
      `http://${device.deviceIp}/ISAPI/Intelligent/FDLib/FaceDataRecord?format=json`,
      { method: "POST", headers: { Authorization: "Digest ..." }, body: form }
    );
    // log
  },
});
```

### Çoklu Yüz / Çoklu Cihaz
- Bir çalışanın **birden fazla cihaza** push edilmesi gerekiyorsa, her cihaz için ayrı action çağrısı
- Hata yönetimi: bir cihazda başarısız olsa diğerlerine devam et
- Audit log: `faceUploads` tablosu
