## İŞ 1 — Convex aşırı function-call sorunu → bridge backoff (TAMAMLANDI, CANLIDA)

### Teşhis
Convex dashboard'da günde ~80K function call görüldü (%48.9 query + %46.9 HTTP Action,
neredeyse simetrik). Sebep: Hetzner'daki `ide-mqtt-bridge` daemon'u `/ide-bridge/poll`
endpoint'ini **2 saniyede bir** poll ediyordu; her poll = 1 HTTP Action + 1 query
(`listPendingForBridge`) → çift sayım. Kuyruk %99 boş olsa bile ölü trafik.

### Çözüm (uygulandı, canlıda doğrulandı)
Daemon'a **adaptive backoff** eklendi — sabit `setInterval` yerine self-scheduling
`setTimeout` zinciri:
- Kuyruk boşken: **60s** (`IDLE_POLL_INTERVAL_MS`)
- Komut akarken: **2s** (`POLL_INTERVAL_MS`, busy)
- `pollCommands` bool döndürür (`ops.length > 0`); boş poll IDLE'a düşer, op bulunca BUSY.

**Doğrulandı:** boş poll zaman damgaları tam 60s aralıkla geldi (20:06:59 → 20:07:59 →
... → 20:12:00). ~30× azalma. Servis `active`, MQTT bağlı.

## İŞ 2 — Üç güvenlik açığı düzeltmesi (KOD HAZIR, DEPLOY EDİLMEDİ)

External bir security review üç açık raporladı; üçü de kodda zincirleriyle doğrulandı

### Vuln 1 — Email Verification Bypass (High) ✅
**Sorun:** `convex/auth.ts` `profile()` `verified=false`'u yalnızca `companyName` varken
set ediyordu; davet/admin akışı companyName göndermez → `verified=undefined`. Saldırgan
companyName'siz signUp atıp guard'ı (`getCurrentUser`: `verified===false`) atlar, sonra
`ensureProjectForNewUser` ile otomatik `project_admin` olur.

**Düzeltme:**
- [convex/auth.ts](../convex/auth.ts) `profile()` artık **her zaman `verified: false`** döner.
  `companyName` sadece `firstCompanyName` için kullanılır, verified ile ilgisi yok.
- `verified=true`'ya yükseltme yalnızca doğrulanmış kanallarda:
  - Self-signup → [emailVerification.confirm](../convex/emailVerification.ts) (mevcut, satır 97)
  - Davet → [invites.consume](../convex/invites.ts) (eklendi, `verified: true` patch)
  - İlk-admin → [users.initializeAdmin](../convex/users.ts) (eklendi)
- `initializeAdmin` `authedMutation` → ham `mutation` + manuel `getAuthUserId`'e çevrildi.
  Sebep: ilk admin signUp anında `verified=false`, `authedMutation` guard'ına takılırdı
  (yumurta-tavuk). Güvenlik: setup secret + "henüz admin yok" kontrolü ile sağlanıyor.

### Vuln 2 — Unauthenticated Account Takeover (High) ✅
**Sorun:** `sendEmployeeSetupEmail` public `action()`, auth yok. Anonim çağrıyla hedef
`employeeId` + saldırgan e-postası → setup token saldırgana yazılır → çalışan mobil
hesabı ele geçirilir.

**Düzeltme** ([convex/actions/sendEmail.ts](../convex/actions/sendEmail.ts)):
- `sendEmployeeSetupEmail` → `authedAction` + `employees.getById` ile proje yetki kontrolü
  (yetkisiz caller `null` alır → erken return).
- `sendUserInviteEmail` → `authedAction`.
- `sendLateNotification`, `sendVerificationEmail` → `internalAction` (sadece scheduler'dan
  çağrılıyorlardı).
- [employeeAuth.create/update](../convex/employeeAuth.ts) → `internalMutation`.
- Çağrı yerleri `api.` → `internal.` güncellendi: `cardReadings.ts:1932`,
  `emailVerification.ts:56`, `setPassword.ts:35`.
- Frontend `useAction` çağrıları (3 yer) korundu — action public kaldı ama auth-guard'lı.

### Vuln 3 — HTML Injection in Email Templates (Medium) ✅
**Sorun:** `renderEmailTemplate` `heading/body` vb. ham interpolate ediyordu; project_admin
çalışan adına `<a href=phishing>` enjekte edip Resend altyapısından phishing maili gönderebilir.

**Düzeltme:** `escapeHtml` helper eklendi; `firstName/lastName`, `projectName`,
`employeeName/lateTime`, `name` interpolasyondan önce escape ediliyor.
- **NOT:** Sabit template HTML'i ve **subject satırları escape EDİLMEDİ** — subject email
  header'ıdır, HTML render edilmez; orada escape `&amp;`'yi düz metin gösterir. (Review
  finder'ı subject'leri yanlış flag'ledi; bilinçli olarak reddedildi.)
